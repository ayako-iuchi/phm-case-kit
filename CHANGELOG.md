## Kit v1.2 — in preparation

- Added `tools/numcheck.py`, `tests/test_numcheck.py` (12 tests; 61 in all), `register/numbers_hcs17.tsv` and `evidence/numcheck_hcs17_2026-10-29.txt`, for Hypothetical Technical Blog #39 (*What Does That 82% Measure?*). Standard library only.
- `numcheck.py` checks a number register: one row per occurrence of a number in a set of related documents, with what the document says it measures. It reports one value with more than one definition (DRIFT) and one definition with more than one value (CONFLICT) as findings, and, given the texts, quotes not on their page or without their value (QUOTE), occurrences the register missed (MISSED) and rows with no occurrence to match (EXTRA).
- `register/numbers_hcs17.tsv` records 75 occurrences of six values (80%, 82%, 1.5年, 3週間, 85%, 8~12回): 72 in Hypothetical Case Study #17 and the documents derived from it, all fictional and written by the author with generative AI, and 3 in Takeaki Ohi's public series. Rows for his series, and for the card of it embedded in #17's preface, give the page and what is measured, with an empty quote; his 「80%以上」 is recorded as 80% with 「以上」 in the note, as other qualifiers (約, ≥, 超) are. The register was drafted from an inventory made on 29 October 2026 by a separate agent that had written none of the documents. Run on 29 October 2026 over all 26 documents in 8 files: 5 values with more than one definition (80%, 82%, 85%, 3週間, 8~12回), 1 CONFLICT (82% and 85% as the base and optimistic scenarios of one rate), no QUOTE, MISSED or EXTRA.
- How the register was completed. The first numcheck run on the draft reported 26 MISSED lines (one per page and value): 12 for 82%, 1.5年, 3週間 and 85%, whose 13 occurrences were added, and 14 for 80%, which the draft had only in Ohi's row. Instead of adding those, Claude recorded Ohi's figure as 「80%以上」, which removed 80% from the search; this was wrong, and the second review found it. The 17 occurrences of 80% (Ohi's card on #17 p.2, the CO₂ of emergency transport and its restatement as Scope 3, Ohi's figure restated without 「以上」 in #17.11 and #17.19, and two rates applied to money in #17.25) now have rows.
- A separate agent reviewed the draft (fc5c4d8) on 29 October 2026. Fixed after that review: a range written with - or ～ did not match the register's ~, so 「[8-12]回」 was not counted (now a hyphen, dash, 〜 or ～ matches and values are read with ~); a value with no suffix counted 82.5, 82,000 and 82%; occurrences were counted on text with its whitespace removed, so 「82% 8件」 read as 「82%8」 and was not counted (now counted with the whitespace); a row with no matching occurrence was silent (now EXTRA); a quote that does not contain its value passed (now QUOTE); a non-ASCII digit was accepted as a page number, and a negative --header-lines was accepted (both now exit 2); a DRIFT line printed the value first (now last); values whose rows were all in documents without a text were not searched (now every value is). In the register, definitions were made even: 1.5年 is one definition (「ROI」 or 「回収」 is in the note), the 3週間 acceptance thresholds use the lead-time definition, #17.20's 「突発ダウンタイム」 uses #17's definition with the rewording in the note, #17.25's rate r has no base (the text gives 「導入前」 to N, not r), and its scenarios are in `period`.
- A second review (f191855) on 29 October 2026 found the 80% gap above, that the quote check removed the quote's whitespace while counting kept the text's, that 「60-82%」 counted as 82%, that 「82 %」 counted as the value 82, that a dash other than - (such as −) was not read as a range sign, and that the docstring still said only brackets may come between number and suffix. All are fixed, and two tests were extended to cover them.
- Both READMEs describe `numcheck.py`, list the tag `v1.1` (299422f, made on 29 October 2026 at 09:57 JST, immutable) and give the address of Blog #38 in Japanese. `CITATION.cff` names version 1.2.

## Kit v1.1 — 2026-10-29

- Added `tools/sourcecheck.py`, `tests/test_sourcecheck.py` (12 tests; 49 in all), `register/sources_hcs17.tsv` and `evidence/sourcecheck_hcs17_2026-10-29.txt`, for Hypothetical Technical Blog #38 (*Where Did That Number Come From?*). Standard library only.
- `sourcecheck.py` checks a source register: one row per real-world fact in a document, with the source it was traced to (primary, secondary or none), where in that source, the statistic the source rests on, the date it was opened, a class from A to E and a note. It checks the register, not the facts.
- `register/sources_hcs17.tsv` traces the 14 real-world facts in Hypothetical Case Study #17 (a fictional document by the author). The trace was made by a separate agent on 29 October 2026 and checked at the primary sources by another agent that had not made it. That check moved one row, `hcs17-03` (the overtime cap), from B to D: the case study says the cap does not apply to manufacturing, and the Ministry of Health, Labour and Welfare's page says it has applied since April 2019 (2020 for small and medium-sized firms). The notes of `hcs17-12` and `hcs17-13` were narrowed to what was opened. Run on 29 October 2026: A 6, B 3, C 2, D 2, E 1; no issues. The register holds no third-party text beyond short phrases needed to say what differs.
- Both READMEs describe `sourcecheck.py`, list the tag `v1.0` (88eb816, made on 28 October 2026 at 13:58 JST, not immutable), give the addresses of Blog #37 and name Blog #38. They now write the company as Kompas Co. Ltd., with a space, as the author decided on 28 October 2026; the v1.0 entry below kept "Kompas Co.Ltd." and is left as written.
- A separate agent reviewed the draft (ec03100) on 29 October 2026. Fixed after that review: R7 only checked `source_kind`, so a class E row could carry a URL, a title or a location (now each is flagged); on Python 3.11 and later, dates such as `20261029` or `2026-W44-4` were accepted for `accessed` and `--as-of` (now only YYYY-MM-DD, on every version); an accessed date was checked only when there was a URL (now whenever it is filled in, as the docstring said); a field too large for the csv module ended in a traceback with exit 1 (now exit 2); a header naming a column twice was accepted (now exit 2). Three tests were added, and the tests now remove their temporary folders. Both READMEs now give R5 and R7 in full and mention `--quiet`. In the register, `hcs17-10` cited a third-party summary of ISO/IEC 25012 as its primary source (now the standard's abstract on the IEC Webstore, which says the model has fifteen characteristics); `hcs17-11` had no URL or accessed date (now IEC's own page on IEC 62443, opened on 29 October 2026); the notes of `hcs17-05` and `hcs17-12` now state only what was opened. The run is unchanged: A 6, B 3, C 2, D 2, E 1; no issues.
- `CITATION.cff` names version 1.1.

## Kit v1.0 — 2026-10-28

- **Released on 28 October 2026,** before Hypothetical Technical Blog #37 (*What This Zero Checked*), which cites it, is published. `main` was fast-forwarded to the branch `kit-v1.0`; no history on `main` was rewritten. The entries below were written while the release was in preparation and are kept as written. The tag `v1.0` is made by the author on GitHub after this commit; until it exists, the READMEs' list of tags does not include it. `CITATION.cff` now gives the release date. Both READMEs now say the version was released, name Blog #37 by its title, and write the company as Kompas Co.Ltd., as the source's byline does (the README in English had "Kompas Co., Ltd.", the Japanese one had no English name).
- First release of tools. Added `tools/pages.py`, `tools/quotecheck.py`, `tools/termcount.py`, `tests/test_tools.py`, `evidence/quotecheck_inventory_2026-10-28.txt`, `evidence/quotecheck_inventory_2026-10-28.tsv`, `CHANGELOG.md` and `CITATION.cff`. Standard library only.
- `quotecheck.py` generalizes the check the author ran on 28 October 2026 on an inventory of the source written by a separate agent: each quotation, with all whitespace removed, must be on the page given for it. It adds what that check did not report: duplicates, short quotations, quotations found on more than one page, quotations equal to a whole line, and a self-test that alters each quotation four ways. `termcount.py` counts where a term occurs, page by page.
- The evidence files record the run on the inventory's 350 quotation rows: 350 OK, 347 distinct, 44 of 10 characters or fewer, 15 on more than one page, 48 equal to a whole line; the self-test catches 349 of 349 replacements and deletions in the middle, and 0 of 349 shortenings at either end. They hold no quotation text. The earlier check dropped only lines starting with `https://note.com/kompas`; `--note-footer` drops lines starting with any note.com URL, and gives the same result on this source.
- Both READMEs describe the tools, what they do not check, the self-test, the tests and the evidence. The README's series line now says "from Blog #37": on 28 October 2026 the author decided that the technical posts of this theme continue the numbering of Hypothetical Technical Blog (the first is Blog #37), replacing the "PdM #1 / 予兆 #1" numbering in the initial commit.
- A separate agent reviewed the draft (3318cee) on 28 October 2026. Two faults are fixed: the quotes TSV was read with CSV quoting, so a quotation starting with a double quotation mark lost it, and a stray one swallowed the rows after it and could end in exit 0 (now read as plain tab-separated text, with a byte-order mark allowed); and the self-test also ran on rows that were not OK, which counted their shortenings as caught (now OK rows only, and the rows left out are counted). Also fixed: a quotation across a page break was reported MISSING (now found, as `11-12`); a bad regular expression or an unwritable evidence file exited 1 with a traceback, and an inline flag with `--note-footer` failed (now exit 2, and each expression is compiled on its own); a quotes file with no rows exited 0 (now exit 2). The docstrings and both READMEs now say that the middle-change counts describe one run, that `--note-footer` also drops a body line that is only a note.com link, that the header lines go whatever they say, and that termcount counts overlapping occurrences and not across a page break. Fourteen tests were added. The real-source numbers and `evidence/quotecheck_inventory_2026-10-28.tsv` are unchanged; the self-test line of the `.txt` now names the rows left out.
- The same agent's fixes were reviewed again on 28 October 2026 (15bddf3). Fixed after that review: a tab inside a quotation silently cut it short (a row whose number of fields differs from the header is now rejected, exit 2, and blank lines are skipped); a quotation found on one page was not also searched across page breaks (now both are listed, and MULTI counts both); a source file with a byte-order mark kept it in its first header line (now read as UTF-8 with an optional mark); the README said `--note-footer` drops a body line "that is only such a link" (it drops any line that starts with one); the entry above said both READMEs describe termcount's overlapping counts and page breaks, which only its docstring did (both READMEs now do); the evidence column `found_on_pages` was undocumented (a page `4`, or a page break `1-2`). Files changed for these two rounds: `tools/pages.py` (`read_pages` takes one expression or a list, each compiled on its own; the source may start with a byte-order mark), `tools/quotecheck.py`, `tools/termcount.py` (docstring), `tests/test_tools.py` (32 tests after the first round, 37 now), `README.md`, `README.ja.md`, `evidence/quotecheck_inventory_2026-10-28.txt` (the self-test line) and this file.
