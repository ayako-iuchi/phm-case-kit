# phm-case-kit

連載「**一つのラインから国内外の全拠点へ──架空の製造業で学ぶ全社DXと予兆管理**」（Hypothetical Technical Blog、Blog #37〜）の再現キットです。

架空事例の文書に出てくる引用・数値・時点のある事実を、**公開資料だけ**で照合するための道具を置きます。

English: [README.md](README.md)

## 使い方

出典は利用者が自分で用意します。頁の区切りを残して抽出します。

    pdftotext -layout source.pdf source.txt

引用は、列 `id`、`page_from`、`page_to`、`quote` を持つタブ区切りのファイルに書きます（見出しの行が必要。ほかの列は無視します）。

    python3 -I tools/quotecheck.py source.txt quotes.tsv --note-footer --mutate --evidence results.tsv
    python3 -I tools/termcount.py source.txt "Predictive Management" "Predictive Maintenance" --pages 1-119 --note-footer

`--note-footer` は、note.com のURLで始まる行（note から印刷した頁のフッター。本文の行でも、そのURLで始まるものは除く）を除きます。`--header-lines`（既定は1）は、中身にかかわらず、各頁の上からその行数を除きます。TSV の中の二重引用符はふつうの文字として読みます。欄にタブや改行は入れられず、欄の数が見出しと違う行は受け付けません。終了コードは、すべて OK なら 0、そうでない行があれば 1、入力の誤りは 2 です。

**quotecheck が確かめること。** 引用と頁の両方から空白をすべて除き、引用が示した頁の部分文字列であるかを見ます。頁の区切りをまたぐ引用は、またいだものとして見つけます（`11-12` のように出します）。それ以外の正規化はしません。「」と ""、全角と半角は別の文字のままです。判定は `OK`、`ELSEWHERE`（別の頁にある。その頁を出す）、`MISSING` です。印は、OK がどれだけの意味を持つかを示します。`SHORT`（既定で10字以下）、`MULTI`（複数の頁にある）、`DUP`（前の行と同じ文）、`LINE`（頁の1行そのもの。多くは見出し）。

**確かめないこと。** 引用が文脈に沿っているか、正しい人に帰属しているか、使った主張を支えているか。抽出の不具合と出典の誤りも区別できません。照合するのは保存したPDFで、今の頁ではありません。

**自己試験（`--mutate`）。** OK で4字以上の引用ごとに4通りの改変を作り、照合で何件を見つけられるかを数えます。先頭か末尾の1字を削ったものは、決して見つかりません。短くした引用も頁にはあるからです。切り詰めた引用は、この照合を通ってしまいます。途中の改変が見つかるかは文によるので、数は1回の実行の結果で、保証ではありません（`evidence/` の棚卸しでは349件中349件）。

**証拠ファイル**（`--evidence`）には、番号、頁、字数、判定、印と、引用がある場所（頁なら `4`、頁の区切りをまたぐなら `1-2`）だけを書き、引用の本文は書きません。

**termcount** は空白を除いてから数えるので、行で分かれた語も見つけます。重なった出現も数え、頁の区切りをまたぐものは数えません。0回は、その頁範囲の抽出テキストにないことだけを意味します。`evidence/` には記事が引く実行結果を置きます。

**sourcecheck** が点検するのは台帳で、事実ではありません。資料を開くことはできません。台帳はタブ区切りで、1行に1つの事実を書きます。列は `id`、`document`、`page`、`statement`、`cited_ref`、`source_kind`（`primary`、`secondary`、`none`）、`source_title`、`issuer`、`edition`、`url`、`location`、`underlying`（その資料自身が拠る統計）、`accessed`（YYYY-MM-DD）、`class`、`note` です。

    python3 -I tools/sourcecheck.py register/sources_hcs17.tsv --as-of 2026-10-29

判定は、`A` 一次資料に書いたとおりある、`B` 一次資料にあるが、限定・前提・年・範囲・単位が落ちたか変わった、`C` 二次資料にしかない、`D` 一次資料と違う、`E` 確かめられない、です。点検は、必須の欄と、B〜E の注記（R1）、許される値（R2）、A・B・D には題と場所のある一次資料（R3）、C には二次資料（R4）、URL には確認日が要り、確認日は YYYY-MM-DD の形で `--as-of` 以前であること（R5）、id の重複（R6）、E には資料なし（`source_kind` が none で、題・URL・場所が空）（R7）です。見出しに同じ列名が2度ある台帳や、読めないほど大きい欄は入力の誤りです。`--quiet` は集計だけを出します。終了コードは、指摘がなければ 0、あれば 1、入力の誤りは 2 です。2つの判定の境目にある事実は人の判断で、注記にその理由を書きます。`register/sources_hcs17.tsv` は、Hypothetical Case Study #17（架空の文書）の実在の事実14項目をたどった台帳で、その実行結果を `evidence/` に置きます。

**numcheck** は数値台帳を点検します。関連する文書群の中で数字が出てくるたびに1行とし、その文書がその数字を何の数字として書いているかを記録します。列は `id`、`value`（書かれたとおりの値。`82%`、`1.5年`、`8~12回` など。全角の数字は半角として、範囲は `~` として読む）、`document`、`page`、`quote`（値を含む短い抜き書き。空でもよい）、`measures`（何を測るか）、`unit`、`base`（何に対する割合か）、`period`、`placeholder`（`[82]` のような印があれば `yes`）、`note` です。

    python3 -I tools/numcheck.py register/numbers_hcs17.tsv --text '#17=hcs17.txt' --text '#17.25=hcs17_02.txt'

`DRIFT`（1つの値に定義が2つ以上。`measures`、`unit`、`base` のどれかが違う）と `CONFLICT`（1つの定義に値が2つ以上）を出します。これは人が判断する所見で、誤りではありません。`--strict` を付けると終了コード 1 にします。`--text DOC=PATH`（繰り返し可。1つのファイルにまとめた複数の文書は同じファイルを指せます）を渡すと、抜き書きがその頁にあり、その値を含むか（`QUOTE`）と、各頁に出てくる回数が台帳の行数と合うか（多ければ `MISSED`、少なければ `EXTRA`）も確かめます。台帳のすべての値を、渡したすべてのテキストで探します。全角の数字と記号は半角として読み、括弧と空白（`[82] %`）と、範囲の記号（`~`、`〜`、`～`、ハイフンやダッシュ）の違いを許します（`[8-12]回` は `8~12回` に一致）。直前の数字・カンマ・小数点・範囲の記号（`60-82%` は `82%` ではない）と、直後の数字（接尾辞のない値では直後の `%` と小数・桁区切りも）は別の数とみなします。空白を残したテキストで数えるので、2行に分かれた数字はつなげません。全部を棚卸ししたつもりの文書だけを渡してください。`--header-lines`（既定 0）と `--note-footer` は quotecheck と同じく行を除き、`--quiet` は集計だけを出します。終了コードは、指摘がなければ 0、`QUOTE`、`MISSED`、`EXTRA` があれば 1（`--strict` では `DRIFT`・`CONFLICT` も 1）、入力の誤りは 2 です。`register/numbers_hcs17.tsv` は、Hypothetical Case Study #17 と派生文書（すべて筆者が生成AIで作った架空の文書）に出てくる6つの値（80%、82%、1.5年、3週間、85%、8~12回）の75か所を記録した台帳です。うち72か所が HCS #17 と派生文書、3か所が大井氏の公開出典です。大井氏の公開出典の行と、#17 の前書きに埋め込まれたそのカードの行は、頁と何を測るかだけで、氏の文章は入れていません。実行結果は `evidence/` に置きます。

**datecheck** は、日付によって真偽が変わる事実の台帳を点検します。3つの日付を分けて記録します。文書の日付（`doc_date`。上限しか分からなければ `<=DATE`）、事実を決める出来事の日付（`event_date`。年、年月、年月日）、資料を開いた日（`accessed`）です。加えて、再確認の期限（`recheck_by`）を持ちます。ほかの列は `id`、`document`、`page`、`statement`、`event`、`status_then` と `status_now`（`true`、`false`、`unknown`）、`source_title`、`url`、`class`、`note` です。

    python3 -I tools/datecheck.py register/dated_hcs17.tsv --as-of 2026-10-29

判定は、`CURRENT` 文書の日付でも今も成り立つ、`SUPERSEDED` 当時の資料としては成り立つが、引いたものが新しい版に置き換わった（文書より前に置き換わっていた場合も含む）、`STALE` 当時は成り立ち今は成り立たない、`WRONG-THEN` 当時も成り立たない、`UNDATED` 日付で真偽が変わるのに日付がない、`CANNOT` 確かめられない、です。点検は、必須の欄（`recheck_by`、CANNOT 以外の資料名、SUPERSEDED・STALE・WRONG-THEN の出来事の日付、CURRENT 以外の注記を含む）（T1）、許される値と日付の形（T2）、判定と status の一致（UNDATED で、当時成り立たない行や、当時成り立ち今は成り立たない行も指摘）（T3）、後知恵（T4。文書より後の出来事で WRONG-THEN にしている行、文書より前の出来事で STALE にしている行、`--as-of` までに起きていない出来事で STALE や SUPERSEDED にしている行。年や年月の出来事はその期間全体で比べる）、URL には確認日が要り、確認日は `--as-of` 以前（T5）、id の重複（T6）、`recheck_by` が `--as-of` 以前で再確認の時期が来た行（T7）です。終了コードは、指摘がなければ 0、あれば 1、入力の誤りは 2 です。`register/dated_hcs17.tsv` は、Hypothetical Case Study #17 と派生文書（すべて筆者が生成AIで作った架空の文書）の、時点のある事実の台帳（21行）です。Blog #40 のための棚卸し（約27件）から、日本の制度・白書・開示と国際規格・フレームワークについての項目で、一次資料で確かめられたものをすべて入れ、海外の法制度、国際機関の数字、確かめきれなかった項目は外しています。複数の文書が使う事実には、1行のものと複数行のものがあります。実行結果を `evidence/` に置きます。

**calccheck** は、文書から写した数字の台帳を計算し直します。1行が1つの数字で、列は `id`、`document`、`page`、`label`、`shown`（文書の表示のまま）、`value`（台帳の単位での小数。82% は 0.82。なければ `-`）、`places`（表示の小数の桁数）、`kind`、`formula`、`of`、`note` です。`kind` は、`input`（文書が与え、導いていない数字）、`derived`（文書自身の式とともに示された数字）、`candidate`（計算の仕方が書かれていない数字について、考えられる読み方の1つ。`of` にその数字の id）、`placeholder`（`[X]` など空けてある数字や、文書が与えていない数字）です。式は `+ - * /`、括弧、小数、ほかの行の id で書きます。式は Python として実行せずに構文を解析し、計算は分数で厳密に行います。derived の行を式で指すと、その行の表示値ではなく計算値を使います。表示値をそのまま使うときは、input の行として記録します。行は依存の順に計算します。式は2,000字まで、value は40字まで、places は0〜12、計算値は4,000ビット（約1,200桁）までです。台帳の問題がある行に依存するだけの行は重ねて報告せず、候補がすべて台帳の問題で計算できない数字には `NOREPRO` を出しません。`--quiet` は要約だけを出します。

    python3 -I tools/calccheck.py register/calc_hcs17_25.tsv

計算値が、表示の最後の桁の半単位以内なら一致とします。文書についての指摘は、`MISMATCH`（derived の行が表示どおりにならない）、`NOREPRO`（表示された数字に candidate があるが、どれも再現しない）、`UNRESOLVED`（式が placeholder を必要とする）です。台帳の問題は、必須の欄と許される値（R1）、式の構文や存在しない id（R2）、自分の行に戻る式（R3）、id の重複（R4）です。ゼロ除算と、大きさの上限を超える計算値も R2 で、循環はその輪のすべての行を R3 で示します、表示値のない行を指す `of`（R5）です。計算は確かめますが、意味は確かめません。時間の率と金額の率の区別はできません。終了コードは、何もなければ 0、指摘があれば 1、入力の誤りは 2 です。`register/calc_hcs17_25.tsv` は、事業計画書の骨子テンプレート Hypothetical Case Study #17.25（筆者が生成AIで作った架空の文書）の台帳で、#17 の表（p.7、画像）に印刷された値を1つ含みます。文書が書いていない読み方の行がいくつかあり、それぞれ注記にそう書いてあります。実行結果を `evidence/` に置きます。

## 決まり

- **事例はすべて架空です。** 事例の文書（Hypothetical Case Study #17 とその派生文書）に出てくる企業・人物・数値は、筆者が生成AIを使って作ったもので、実在の企業の記録ではありません。
- **公開資料だけを使います。** 連載の手法の出典は、株式会社KOMPAS（Kompas Co. Ltd.）CEO 大井竹昭氏の公開 note マガジン「予兆管理」です。氏の考えとして書くのは、この公開出典で確かめられるものだけです。英語の表記も、氏の第1回の表記「Predictive Maintenance / Prognostics and Health Management - PHM」に従います。
- **第三者の文章はこのリポジトリに入れません。** 出典のPDFやそのテキストはコミットしません。道具は、利用者が自分で用意したファイルを読みます。
- 記載の企業とは関係がなく、その承認を受けたものでもありません。
