## 使い方

出典は利用者が自分で用意します。頁の区切りを残して抽出します。

    pdftotext -layout source.pdf source.txt

引用は、列 `id`、`page_from`、`page_to`、`quote` を持つタブ区切りのファイルに書きます（見出しの行が必要。ほかの列は無視します）。

    python3 -I tools/quotecheck.py source.txt quotes.tsv --note-footer --mutate --evidence results.tsv
    python3 -I tools/termcount.py source.txt "Predictive Management" "Predictive Maintenance" --pages 1-119 --note-footer

`--note-footer` は、note.com のURLで始まる行（note から印刷した頁のフッター。本文の行でも、そのURLで始まるものは除く）を除きます。`--header-lines`（既定は1）は、中身にかかわらず、各頁の上からその行数を除きます。TSV の中の二重引用符はふつうの文字として読みます。欄にタブや改行は入れられず、欄の数が見出しと違う行は受け付けません。終了コードは、すべて OK なら 0、そうでない行があれば 1、入力の誤りは 2 です。

**quotecheck が確かめること。** 引用と頁の両方から空白をすべて除き、引用が示した頁の部分文字列であるかを見ます。頁の区切りをまたぐ引用は、またいだものとして見つけます（`11-12` のように出します）。それ以外の正規化はしません。「」と ""、全角と半角は別の文字のままです。判定は `OK`、`ELSEWHERE`（別の頁にある。その頁を出す）、`MISSING` です。印は、OK がどれだけの意味を持つかを示します。`SHORT`（既定で10字以下）、`MULTI`（複数の頁にある）、`DUP`（前の行と同じ文）、`LINE`（頁の1行そのもの。多くは見出し）。

**確かめないこと。** 引用が文脈に沿っているか、正しい人に帰属しているか、使った主張を支えているか。抽出の不具合と出典の誤りも区別できません。照合するのは保存したPDFで、今の頁ではありません。

**自己試験（`--mutate`）。** OK で4字以上の引用ごとに4通りの改変を作り、照合で何件を見つけられるかを数えます。先頭か末尾の1字を削ったものは、決して見つかりません。短くした引用も頁にはあるからです。切り詰めた引用は、この照合を通ってしまいます。途中の改変が見つかるかは文によるので、数は1回の実行の結果で、保証ではありません（`evidence/` の棚卸しでは349件中349件）。

**証拠ファイル**（`--evidence`）には、番号、頁、字数、判定、印と、引用がある場所（頁なら `4`、頁の区切りをまたぐなら `1-2`）だけを書き、引用の本文は書きません。

**termcount** は空白を除いてから数えるので、行で分かれた語も見つけます。重なった出現も数え、頁の区切りをまたぐものは数えません。0回は、その頁範囲の抽出テキストにないことだけを意味します。`evidence/` には記事が引く実行結果を置きます。

## 決まり

- **事例はすべて架空です。** 事例の文書（Hypothetical Case Study #17 とその派生文書）に出てくる企業・人物・数値は、筆者が生成AIを使って作ったもので、実在の企業の記録ではありません。
- **公開資料だけを使います。** 連載の手法の出典は、株式会社KOMPAS（Kompas Co.Ltd.）CEO 大井竹昭氏の公開 note マガジン「予兆管理」です。氏の考えとして書くのは、この公開出典で確かめられるものだけです。英語の表記も、氏の第1回の表記「Predictive Maintenance / Prognostics and Health Management - PHM」に従います。
- **第三者の文章はこのリポジトリに入れません。** 出典のPDFやそのテキストはコミットしません。道具は、利用者が自分で用意したファイルを読みます。
- 記載の企業とは関係がなく、その承認を受けたものでもありません。
